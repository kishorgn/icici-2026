URL Design

Work in pairs · Estimated time: 60 minutes

Quick Reference — 5 URL Design Rules
Rule 1
Nouns only — never verbs
✓ /customers   ✗ /getCustomers
Rule 2
Always plural
✓ /accounts   ✗ /account
Rule 3
Lowercase only
✓ /customers   ✗ /Customers
Rule 4
Hyphens for spaces
✓ /fixed-deposits   ✗ /fixedDeposits
Rule 5
Nest to show ownership
✓ /customers/{id}/accounts

Part C — Path variable vs query parameter (20 min)
Use a path variable when… Use a query parameter when…
You need one specific resource by identity
/customers/CUST1001		 You want to filter, sort, or paginate a collection
/customers?city=Mumbai&limit=20

Decide: path variable or query parameter?

OperationYour choiceWrite the URL
Get the customer whose ID is CUST1002
List all customers in Mumbai
Get the 2nd page of 10 transactions for account ACC2200
Delete beneficiary B3311 belonging to customer CUST1001
Rule of thumb: If removing the value makes the URL point to a different resource, it's a path variable. If the URL still makes sense without it, it's a query parameter.
