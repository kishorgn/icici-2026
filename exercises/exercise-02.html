HTTP Status Codes

Work in pairs · Estimated time: 30 minutes

Status Code Bank — use these for Part A & B
200 OK 201 Created 204 No Content 400 Bad Request 401 Unauthorized 403 Forbidden 404 Not Found 500 Internal Server Error
Families: 2xx = Success  ·  4xx = Client error (your mistake)  ·  5xx = Server error (their mistake)
Part A — Banking scenario matching (15 min)

Write the correct status code next to each scenario. Use the code bank above.

  • 1. Customer checks their account balance. The balance is returned successfully.
  • 2. Customer opens a new fixed deposit. The FD record is created in the system.
  • 3. Customer removes a beneficiary. The operation succeeds with nothing to return.
  • 4. Customer enters a mobile number with letters ("98765ABCD0") in a transfer form.
  • 5. Customer's session token expired. They try to view their statement without logging in again.
  • 6. A teller tries to access a customer file they are not authorised to view. They are logged in but don't have permission.
  • 7. Customer calls GET /api/v1/customers/CUST9999. No such customer exists.
  • 8. A NullPointerException crashes the transaction service during a fund transfer attempt.
  • 9. Customer successfully updates only their email address (PATCH request).
  • 10. Customer tries to view another customer's account — they are authenticated but blocked.
Part B — Code families (5 min)

Sort the 8 codes from the bank into the correct family columns.

✅ 2xx — Success ⚠️ 4xx — Client Error 🔥 5xx — Server Error
Part C — 401 vs 403: the most common mix-up (10 min)
401

Unauthorized

"Who are you? Show ID."

No valid session or token. The client is not authenticated at all.

Fix: Log in and get a valid token first.

403

Forbidden

"I know who you are. You can't do this."

Valid token — but the user does not have permission for this resource.

Fix: Request the correct access level.

C3. A developer forgets to send the Authorization header at all. Which code?
