Branch & ATM Finder API Design

Work in pairs · Estimated time: 60 minutes · Gallery walk at the end

The challenge

ICICI Bank needs a new Branch & ATM Finder API so that mobile app users can locate nearby branches and ATMs across India. Your pair is the API design team. Design the 6 endpoints below — choose the right method, write a clean URL, and decide what the expected status code should be.

Part A — Design the 6 endpoints (30 min)

Complete each row. Use /api/v1 prefix for all URLs.

Operation Method URL Status code
List all branches in India
Get details of one specific branch by its ID
Search branches by city (e.g. Mumbai)
List all ATMs belonging to a specific branch
Report that a specific ATM is out of service
Add a newly opened branch to the system
Part B — Sample JSON response (10 min)

Here is a sample response for "Get one branch". Study it, then answer the questions below.

{
  "branchId":   "BR-MUM-001",
  "name":       "ICICI Bank — Bandra West",
  "city":       "Mumbai",
  "state":      "Maharashtra",
  "ifscCode":   "ICIC0001234",
  "address":    "14, Linking Road, Bandra West, Mumbai 400050",
  "phone":      "+91-22-26408001",
  "openHours":  "Mon–Sat 09:30–15:30",
  "atmCount":   3,
  "services":   ["Locker", "Forex", "NRI Services"]
}

Questions:

Q1. Which HTTP method and URL returns this response?
Q2. What status code does a successful response carry?
Q3. If branchId: "BR-MUM-999" does not exist, what status code should the API return?
Q4. Add one more field you think this response should have. Write it in JSON format below:
  "": ""
Gallery Walk (10 min)
1
Write your 6 endpoint designs on the whiteboard or sticky notes — one endpoint per line.
2
Walk to another pair's board. Put a ✓ next to designs you agree with and a ✗ next to ones you'd change.
3
Return to your board. For each ✗, discuss with your partner: is the critique valid? Update if yes.
4
Trainer picks 2–3 differences to discuss with the full class.
Good design debate: There is rarely one single correct answer. Focus on whether the URL follows the 5 rules and whether the method accurately describes the operation.
Self-check before gallery walk
  • All my URLs use only nouns — no verbs anywhere
  • All resource names are plural (branches, not branch)
  • URLs are all lowercase with hyphens — no camelCase
  • Nested paths show ownership (e.g. /branches/{id}/atms)
  • I used GET for the city search with a query parameter, not a path variable
  • The new-branch endpoint uses POST and expects a 201 response
