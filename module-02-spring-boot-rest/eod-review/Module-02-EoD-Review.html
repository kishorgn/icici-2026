PUT vs PATCH
The most common confusion — know the difference
⚡ PUT — Full Replace
Body: ALL fields required
Omit a field: it becomes null
URL: /customers/{id}
Idempotent: yes
Use when: replacing everything
🩹 PATCH — Partial Update
Body: only changed fields
Omit a field: it stays unchanged
URL: /customers/{id}/email
Idempotent: yes
Use when: updating one specific field
Key Concepts — Day 2
@RequestBody
Spring reads the HTTP request body and deserializes JSON → Java object automatically. Jackson does the work. Required for POST, PUT, PATCH.
ResponseEntity
Gives you full control over the HTTP response: status code + body + headers. Without it, Spring always returns 200. Never skip it in a real API.
@PathVariable
Extracts a value from the URL path. /customers/{id} → @PathVariable String id. Used in GET (one), PUT, PATCH, DELETE.
AtomicInteger
Thread-safe counter for ID generation. counter.incrementAndGet() returns next value. Real apps use DB-generated IDs (auto-increment / UUID).
204 No Content
DELETE success returns no body intentionally. ResponseEntity<Void> and .noContent().build(). Postman shows "No Body" — that's correct.
Mutable List
Day 1 used Arrays.asList() (immutable). Day 2 needs new ArrayList<>(List.of(...)) to support add / remove / set operations.
