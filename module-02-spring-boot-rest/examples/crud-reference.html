GET Read Resources

Two GET patterns — list all, or get one by ID:

List AllGET /api/v1/customers
Get OneGET /api/v1/customers/CUST1001
Request BodyNone — GET never has a body
List Response200 OK + JSON array
One Response200 OK + JSON object
Not Found404 Not Found (list = 200 with empty array [])
POST Create a Resource
URLPOST /api/v1/customers
HeadersContent-Type: application/json
Request Body{ "name": "Neha Singh", "email": "neha@email.com", "mobile": "9988776655" }
⚠ ImportantDo NOT include customerId — server assigns it
Success201 Created + full object with server-assigned ID
Response Body{ "customerId": "CUST1004", "name": "Neha Singh", "email": "neha@email.com", "mobile": "9988776655" }
Bad Input400 Bad Request
PUT Full Replace
URLPUT /api/v1/customers/CUST1001
Request Body{ "name": "Arjun S.", "email": "arjun.new@email.com", "mobile": "9000000000" }
⚠ ImportantALL fields required — omitting a field makes it null/empty
Success200 OK + full updated object
Not Found404 Not Found — no body
Idempotent?Yes — calling PUT twice gives the same result
PATCH Partial Update
URLPATCH /api/v1/customers/CUST1001/email
Request Body{ "email": "arjun.updated@email.com" }
Unchanged fieldsname and mobile stay exactly as they were
Success200 OK + full customer with updated email
Not Found404 Not Found
DELETE Remove a Resource
URLDELETE /api/v1/customers/CUST1001
Request BodyNone
Success204 No Content — empty body (intentional!)
Not Found404 Not Found
2nd call on same ID404 — already deleted
PUT vs PATCH — The Critical Difference

Scenario: Customer wants to update only their email. Name and mobile should stay the same.

❌ With PUT

Must send everything:

{"name":"Arjun",
"mobile":"9876543210",
"email":"new@x.com"}

Omit name → name becomes null!

✓ With PATCH

Send only what changed:

{"email":"new@x.com"}

name + mobile untouched ✓
