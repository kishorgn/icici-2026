GET vs POST — the most common confusion

GET — Read

Read. Never changes anything on the server.
No request body.
Safe to call 100 times — same result every time.
Returns 200 with data in the response body.

POST — Create

Create. Makes a brand new resource.
Requires a request body with the new data.
Each call creates a new record — calling twice makes two.
Returns 201 with the new resource in the body.
PUT vs PATCH — the subtle difference

PUT — Full replace

Must send ALL fields in the request body.
Fields not sent get wiped to null or default.
Used for admin-level full replacements.
Risk: accidentally deleting field values.

PATCH — Partial update

Send only the fields that changed.
Fields not sent are untouched.
Safer for everyday partial updates.
Preferred when users edit one or two fields.
Quick decision guide
Am I reading data? Will this change anything?
→ GET — reads never change data
Am I creating a brand new resource?
→ POST
Am I removing something?
→ DELETE
Am I changing SOME fields of an existing resource?
→ PATCH
Am I replacing an entire resource (all fields)?
→ PUT
The golden rule: Never put a verb in your URL. The HTTP method IS the verb. POST /createAccount is wrong. The right way is POST /accounts.
