401 vs 403 — the most misused pair

401 Unauthorized

"Who are you? Show ID."
No token, or the token is invalid/expired.
The server cannot identify who is making the request.
Fix: Log in and get a valid token.
Like arriving without an ID at a guarded gate.

403 Forbidden

"I know who you are. You cannot do this."
Valid token — but not enough permissions.
The server knows exactly who is asking, and says no.
Fix: Request the correct access level.
Like having an ID but not being on the guest list.
Choosing the right 2xx code
Code Use it when… What NOT to do
200 Reading data (GET), updating an existing resource (PUT/PATCH) Never return 200 for a CREATE operation
201 Creating a new resource (POST) Never return 200 when something new was made
204 Deleting (DELETE) — nothing meaningful to return Never return 200 with an empty body — use 204
Remember: The status code is how the server tells the client what happened. Getting it wrong breaks every client that depends on your API — apps, tests, and other services.
