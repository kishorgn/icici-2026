MySQL + Spring Boot — Setup Reference

Module 04 | Day 4 | ICICI Bank API Services Training

📦 pom.xml — MySQL Dependency

Spring Boot 3.x uses the com.mysql groupId (changed from mysql in older versions). No version needed — Spring Boot's parent POM manages it.

<dependency>
  <groupId>com.mysql</groupId>
  <artifactId>mysql-connector-j</artifactId>
  <scope>runtime</scope>
</dependency>

🔗 JDBC URL — Parameters Explained

jdbc:mysql://localhost:3306/icicidb?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
PartMeaning
jdbc:mysql://Protocol — tells Spring to use the MySQL JDBC driver
localhost:3306Host and port of the MySQL server (3306 is the default MySQL port)
/icicidbDatabase name — must exist before the app starts
useSSL=falseDisables SSL for local dev (avoids certificate warnings)
serverTimezone=UTCPrevents timezone mismatch warnings between JVM and MySQL
allowPublicKeyRetrieval=trueRequired for MySQL 8+ with the caching_sha2_password auth plugin

🛠️ Create the Database

Run these commands once before starting the Spring Boot app:

# Connect to MySQL
mysql -u root -p

-- Create the database
CREATE DATABASE icicidb
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

-- Confirm it was created
SHOW DATABASES;

exit
💡 utf8mb4 supports all Unicode characters including emojis. Always use it instead of plain utf8 for new projects.

⚙️ application-dev.properties

spring.datasource.url=jdbc:mysql://localhost:3306/icicidb\
?useSSL=false&serverTimezone=UTC\
&allowPublicKeyRetrieval=true
spring.datasource.driver-class-name=\
  com.mysql.cj.jdbc.Driver
spring.datasource.username=root
spring.datasource.password=root

spring.jpa.database-platform=\
  org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true

🗄️ ddl-auto — When to Use Each Value

ValueWhat Hibernate Does on StartupSafe For
createDrops ALL tables, recreates from entities — loses all dataNever use when data matters
create-dropCreates on start, drops on shutdown — data gone every timeUnit / integration tests
updateAdds missing columns and tables; never removes existing columnsDev — data is preserved between restarts
validateChecks schema matches entities; fails fast on mismatch — makes no changesProduction — proves schema is correct
noneIgnores schema completely — you manage DDL yourselfWhen DBA controls the schema
⚠️ Never deploy ddl-auto=create to production — it will drop every table and delete all customer data on the next deployment.

🚨 Common MySQL Connection Errors and Fixes

Error MessageMost Likely CauseFix
Communications link failure MySQL server is not running Start MySQL: brew services start mysql (macOS) or sudo service mysql start (Linux)
Unknown database 'icicidb' Database does not exist yet Run: CREATE DATABASE icicidb CHARACTER SET utf8mb4;
Access denied for user 'root'@'localhost' Wrong password in properties file Check spring.datasource.password matches your MySQL root password
Public Key Retrieval is not allowed Missing URL parameter Add allowPublicKeyRetrieval=true to the JDBC URL
Schema-validation: missing table ddl-auto=validate but table does not exist Switch to ddl-auto=update for dev, or create the table manually
Table 'icicidb.xyz' doesn't exist Entity exists but table was never created Confirm ddl-auto=update and restart the app

💻 Useful MySQL Commands

-- List all databases
SHOW DATABASES;

-- Switch to icicidb
USE icicidb;

-- List tables
SHOW TABLES;

-- Inspect a table structure
DESCRIBE customers;

-- Query data
SELECT * FROM customers;

-- Count rows
SELECT COUNT(*) FROM transactions;

✅ Verify Spring Boot is Connected

In startup logs, look for:

HikariPool-1 - Starting...
HikariPool-1 - Start completed.
-- no red WARN/ERROR lines about datasource

Via Actuator health endpoint:

GET http://localhost:8080/actuator/health

-- Expected response:
{
  "status": "UP",
  "components": {
    "db": {
      "status": "UP",
      "details": {
        "database": "MySQL",
        "validationQuery": "isValid()"
      }
    }
  }
}
💡 If you see "database": "MySQL" in the health response, the connection is working correctly.
