Module 4 — Day 4 · Student Reference

Fund Transfer REST API — Specification & Reference Base: http://localhost:8080 Format: JSON
Overview
Base URL http://localhost:8080/api/v1/transactions

What you are building

A Fund Transfer REST API that records money movements between bank accounts. Each transaction is persisted to a MySQL table (transactions) and given a human-readable ID like TXN1001.

No authentication required for this exercise — focus on entity design, JPA, and REST structure.
Transaction Object

This is the JSON structure used in both requests and responses.

Field Type Required? Description
transactionId String Generated Auto-assigned by the server. Format: TXN1001, TXN1002, … Do not send this in a POST request.
fromAccountId String Required The account debited. Example: ACC001
toAccountId String Required The account credited. Example: ACC002
amount BigDecimal Required Transfer amount — up to 2 decimal places. Example: 5000.00
Must be positive. Use BigDecimal in Java, not double.
transactionType String Required Either DEBIT or CREDIT
remarks String Optional Free-text note. Example: Monthly rent
Endpoints
POST
/api/v1/transactions
Create a new fund transfer
Request Body
{
  "fromAccountId":    "ACC001",
  "toAccountId":      "ACC002",
  "amount":          5000.00,
  "transactionType": "DEBIT",
  "remarks":         "Monthly rent payment"
}
Response — 201 Created
{
  "transactionId":   "TXN1001",    // generated by the server
  "fromAccountId":   "ACC001",
  "toAccountId":     "ACC002",
  "amount":          5000.00,
  "transactionType": "DEBIT",
  "remarks":         "Monthly rent payment"
}
201 Transaction created successfully
400 Bad request — missing required fields
500 Server error — check MySQL connection
Tip: The server generates transactionId automatically. Do not include it in the request — it will be ignored or cause an error.

GET
/api/v1/transactions/account/{accountId}
Retrieve all transactions involving an account (as sender or receiver)
Path VariableTypeExample
accountId String ACC001
Example Request
GET /api/v1/transactions/account/ACC001
Response — 200 OK
// Returns transactions where ACC001 is fromAccountId OR toAccountId
[
  {
    "transactionId":   "TXN1001",
    "fromAccountId":   "ACC001",    // ACC001 sent this
    "toAccountId":     "ACC002",
    "amount":          5000.00,
    "transactionType": "DEBIT",
    "remarks":         "Monthly rent payment"
  },
  {
    "transactionId":   "TXN1002",
    "fromAccountId":   "ACC003",
    "toAccountId":     "ACC001",    // ACC001 received this
    "amount":          12000.50,
    "transactionType": "CREDIT",
    "remarks":         "Salary credit"
  }
]
200 Returns combined list of sent and received transactions. Empty array [ ] if account has no transactions.
How this works: The repository calls findByFromAccountId() and findByToAccountId() separately, then the controller merges both lists into one response.
Transaction ID Generation

Format: TXN + sequential number starting at 1001

IDs are generated in the controller using an AtomicInteger counter. The counter starts at 1000, and incrementAndGet() is called on each POST, giving TXN1001, TXN1002, and so on.

Counter setup (class-level field in the controller)
// Declare at class level — NOT inside the method
private final AtomicInteger counter = new AtomicInteger(1000);

// Inside POST handler:
t.setTransactionId("TXN" + counter.incrementAndGet());
Note: The counter resets to 1001 every time the application restarts (it lives in memory, not in MySQL). This is expected for today's exercise.

Things to Remember
BigDecimal, not double: Always use BigDecimal for the amount field. Using double can cause rounding errors in financial calculations.
jakarta.persistence, not javax: Spring Boot 3.x uses jakarta.persistence.* imports. If you see a red javax.persistence import, fix it.
@Table(name = "transactions"): Add this annotation to the entity. Without it, Hibernate may use the class name "Transaction" which is a reserved word in MySQL.
Repository ID type: Since transactionId is a String, your repository must extend JpaRepository<Transaction, String> — not JpaRepository<Transaction, Long>.
