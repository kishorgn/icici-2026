Spring Profiles — How They Work

Spring Boot loads application.properties first (always), then the profile-specific file on top. Profile-specific keys override common keys.

src/main/resources/
├── application.properties          # Always loaded — common settings
├── application-dev.properties      # Loaded when profile = dev
└── application-prod.properties     # Loaded when profile = prod

Three Ways to Activate a Profile

#MethodSyntaxOverrides
1In application.propertiesspring.profiles.active=devNothing (lowest precedence)
2JVM argumentjava -Dspring.profiles.active=prod -jar app.jarProperties file
3Environment variableexport SPRING_PROFILES_ACTIVE=prodBoth of the above

MySQL Integration — Key Points

Dependency (pom.xml)

<dependency>
  <groupId>com.mysql</groupId>          <!-- Spring Boot 3.x groupId -->
  <artifactId>mysql-connector-j</artifactId>
  <scope>runtime</scope>
</dependency>

JDBC URL — What Each Parameter Does

jdbc:mysql://localhost:3306/icicidb?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
              ─────┬─────  ──┬──  ───────────────────────────────────────────────────────────────
                 host    port  icicidb = database name; params prevent SSL & timezone errors

Hibernate creates tables automatically (dev only)

With ddl-auto=update, Hibernate reads your @Entity classes and runs CREATE TABLE SQL for you on startup. You do not need to write SQL scripts. This is what makes development fast.

💡
Verify with MySQL: USE icicidb; SHOW TABLES; — you should see a row for each entity class in your project.

ddl-auto Values Ranked by Risk

ValueActionUse In
createDrops ALL tables, recreates — loses all dataNever in production
updateAdds missing columns/tables, preserves dataDev only
validateChecks schema, makes no changes, fails fast on mismatchProduction
noneDoes nothingDBA-managed schemas

Pagination & Sorting — The Full Mental Model

Why Pagination?

A banking system with 10 million accounts cannot return them all in one API response. Pagination returns a window of results and tells the client how many total records exist.

Repository — Enable Pagination in One Line

// Add Page<T> findAll(Pageable pageable) to your repository
public interface CustomerRepository extends JpaRepository<Customer, String> {
    Page<Customer> findAll(Pageable pageable);
}

Controller — Accept Pageable Parameters

@GetMapping("/page")
public Page<Customer> getPage(
        @RequestParam(defaultValue="0") int page,
        @RequestParam(defaultValue="5") int size,
        @RequestParam(defaultValue="name") String sort) {
    Pageable p = PageRequest.of(page, size, Sort.by(sort));
    return repo.findAll(p);
}

URL Pattern & Page Response Shape

URLMeaning
GET /api/v1/customers/page?page=0&size=5&sort=namePage 1, 5 items, sorted by name A→Z
GET /api/v1/customers/page?page=1&size=5&sort=namePage 2 (items 6–10)
GET /api/v1/customers/page?page=0&size=10&sort=balance,descTop 10 by balance, highest first

Page<T> Response Fields

FieldDescription

Top Mistakes — Day 4

  • ✗ Mistake
    ddl-auto=create in dev
    Every app restart drops all tables and recreates them — losing all data you inserted via POST. Use ddl-auto=update in dev to preserve data between restarts.
  • ✗ Mistake
    MySQL server not running → "Communications link failure"
    The JDBC URL is correct but MySQL process is not started. Fix: brew services start mysql (macOS) or sudo service mysql start (Linux), then restart the app.
  • ✗ Mistake
    Database "icicidb" does not exist
    MySQL starts but the database was never created. Fix: CREATE DATABASE icicidb CHARACTER SET utf8mb4; in a MySQL shell before starting the app.
  • ✗ Mistake
    javax.persistence instead of jakarta.persistence
    Spring Boot 3.x uses the Jakarta EE namespace. Any import javax.persistence.* causes compile errors. Fix: change to import jakarta.persistence.*.
  • ✓ Correct
    Profile-specific values override common values
    If both application.properties and application-dev.properties set the same key, the dev-profile value wins. This is how you override defaults per environment.
  • ✓ Correct
    BigDecimal for all monetary amounts
    double has floating-point precision errors (0.1 + 0.2 ≠ 0.3 in Java). Banking applications always use BigDecimal for amounts.
