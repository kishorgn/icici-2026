Exercise 01 — Spring Profiles Setup

Module 04: Spring Profiles + MySQL | ICICI Bank API Services | Day 4

⏱ 45 Minutes · Individual
Difficulty: Intermediate
Starting point: Day-3 project
Goal: Split config into dev / prod profiles using .properties

Context

01

So far the project has a single application.properties file. When the same app runs on a developer's laptop and on a production server, the database credentials, logging levels, and connection settings are different. Hard-coding prod values is a security risk; Spring Profiles solve this cleanly.

By the end of this exercise you will have three properties files:

  • application.properties — common settings shared by all profiles
  • application-dev.properties — developer laptop (MySQL local, show-sql=true)
  • application-prod.properties — production (MySQL credentials from env vars)

Step 1 — Add MySQL Dependency

01

Open pom.xml. Replace any H2 dependency with the MySQL connector. Spring Boot 3.x uses the com.mysql groupId:

pom.xml
<!-- MySQL JDBC driver -->
<dependency>
  <groupId>com.mysql</groupId>
  <artifactId>mysql-connector-j</artifactId>
  <scope>runtime</scope>
</dependency>
💡 No version number needed — Spring Boot's parent POM manages the version for you.

Step 2 — Create application.properties (common)

02

This file holds settings that apply to every profile. The spring.profiles.active line picks the profile to load on top of this.

src/main/resources/application.properties
server.port=8080
spring.application.name=icici-banking-api

# Active profile — change to 'prod' for production
spring.profiles.active=dev

# Actuator endpoints
management.endpoints.web.exposure.include=health,info,metrics
management.endpoint.health.show-details=always

# App info visible at /actuator/info
info.app.name=ICICI Banking API
info.app.version=1.0.0
info.app.trainer=Kishor

Step 3 — Create application-dev.properties

03

Dev profile points to your local MySQL. First create the database if it does not exist:

mysql -u root -p
CREATE DATABASE icicidb CHARACTER SET utf8mb4;
exit

Then create the profile file:

src/main/resources/application-dev.properties
spring.datasource.url=jdbc:mysql://localhost:3306/icicidb?useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=root
spring.datasource.password=root

spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
💡 ddl-auto=update — Hibernate automatically creates or alters tables to match your entities. Safe for dev; never use in production.

Step 4 — Create application-prod.properties

04

Production credentials must never be hard-coded. Use the ${VAR:default} syntax so they come from environment variables:

src/main/resources/application-prod.properties
spring.datasource.url=${DB_URL:jdbc:mysql://localhost:3306/icicidb}
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=${DB_USERNAME:root}
spring.datasource.password=${DB_PASSWORD:root}

spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=false
💡 ddl-auto=validate — Hibernate checks that the schema matches the entities but makes no changes. The app fails fast if there is a mismatch.

Step 5 — Three Ways to Activate a Profile

05
MethodCommand / SettingWhen to use
1. In properties file spring.profiles.active=dev Default for local dev
2. JVM argument java -Dspring.profiles.active=prod -jar app.jar CI/CD scripts, overrides file
3. Environment variable export SPRING_PROFILES_ACTIVE=prod Docker, Kubernetes, cloud deploy
⚠️ The JVM argument and environment variable both override spring.profiles.active in the properties file — they take higher precedence.

Step 6 — Run and Verify

06
A
Start the app normally (dev profile active by default):
mvn spring-boot:run
B
Look for this line in startup logs:
The following 1 profile is active: "dev"
C
Check health endpoint confirms MySQL is connected:
GET http://localhost:8080/actuator/health
D
Switch to prod profile via JVM arg:
mvn spring-boot:run -Dspring-boot.run.jvmArguments="-Dspring.profiles.active=prod"
E
Logs now show: The following 1 profile is active: "prod"
✅ Checkpoint — You should see the active profile name in startup logs, and /actuator/health should show "status": "UP" with MySQL listed under components.

Challenge (If You Finish Early)

★
  1. Add a spring.jpa.properties.hibernate.show_sql entry only in the dev profile and confirm it appears in dev logs but not prod logs.
  2. Create a third profile called test — same MySQL URL but ddl-auto=create-drop so tables are rebuilt fresh for each test run.
  3. In application.properties, add info.app.env=${spring.profiles.active} and observe that /actuator/info now shows the active profile name.
