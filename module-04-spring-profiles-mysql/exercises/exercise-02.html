📋 Use Case — ICICI Fund Transfer Tracking

ICICI Bank needs to track every fund transfer between accounts. When a customer initiates a transfer, the system records the transaction with a unique ID (TXN1001, TXN1002, …), the sender's account, the receiver's account, the amount, and a transaction type (DEBIT or CREDIT).

Your task: build the REST API that records and retrieves these transactions, persisted in MySQL.

Step 1 — Create the Transaction Entity

01

Create Transaction.java in the model package. Use BigDecimal for the amount — financial values must never be stored as double.

src/main/java/com/icici/banking/model/Transaction.java
package com.icici.banking.model;

import jakarta.persistence.*;
import java.math.BigDecimal;

@Entity
@Table(name = "transactions")
public class Transaction {

    @Id
    @Column(name = "transaction_id")
    private String transactionId;       // TXN1001, TXN1002, ...

    @Column(name = "from_account_id", nullable = false)
    private String fromAccountId;

    @Column(name = "to_account_id", nullable = false)
    private String toAccountId;

    @Column(nullable = false, precision = 15, scale = 2)
    private BigDecimal amount;

    @Column(name = "transaction_type", nullable = false)
    private String transactionType;     // "DEBIT" or "CREDIT"

    @Column
    private String remarks;

    // Constructors
    public Transaction() {}

    public Transaction(String transactionId, String fromAccountId,
                       String toAccountId, BigDecimal amount,
                       String transactionType, String remarks) {
        this.transactionId   = transactionId;
        this.fromAccountId  = fromAccountId;
        this.toAccountId    = toAccountId;
        this.amount         = amount;
        this.transactionType = transactionType;
        this.remarks        = remarks;
    }

    // Getters & Setters (generate with IDE: Alt+Insert → Getter and Setter)
    public String getTransactionId()   { return transactionId; }
    public void   setTransactionId(String v) { transactionId = v; }
    public String getFromAccountId()   { return fromAccountId; }
    public void   setFromAccountId(String v) { fromAccountId = v; }
    public String getToAccountId()     { return toAccountId; }
    public void   setToAccountId(String v) { toAccountId = v; }
    public BigDecimal getAmount()      { return amount; }
    public void   setAmount(BigDecimal v) { amount = v; }
    public String getTransactionType() { return transactionType; }
    public void   setTransactionType(String v) { transactionType = v; }
    public String getRemarks()         { return remarks; }
    public void   setRemarks(String v) { remarks = v; }
}
💡 jakarta.persistence.* is the correct import in Spring Boot 3.x. If you see red imports for javax.persistence, you're on the wrong package.

Step 2 — Create TransactionRepository

02

Spring Data JPA generates SQL for you. Declare an interface that extends JpaRepository — you get save, findAll, findById, delete for free. Add two custom finders by naming convention:

src/main/java/com/icici/banking/repository/TransactionRepository.java
package com.icici.banking.repository;

import com.icici.banking.model.Transaction;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.stereotype.Repository;
import java.util.List;

@Repository
public interface TransactionRepository extends JpaRepository<Transaction, String> {

    // Spring Data generates: SELECT * FROM transactions WHERE from_account_id = ?
    List<Transaction> findByFromAccountId(String accountId);

    // Spring Data generates: SELECT * FROM transactions WHERE to_account_id = ?
    List<Transaction> findByToAccountId(String accountId);
}
💡 JpaRepository<Transaction, String> — the second type parameter is the type of the primary key (transactionId is a String).

Step 3 — Create TransactionController

03

Wire up the four endpoints. Use an AtomicInteger counter to generate IDs like TXN1001, TXN1002, … in order:

src/main/java/com/icici/banking/controller/TransactionController.java
package com.icici.banking.controller;

import com.icici.banking.model.Transaction;
import com.icici.banking.repository.TransactionRepository;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.concurrent.atomic.AtomicInteger;

@RestController
@RequestMapping("/api/v1/transactions")
public class TransactionController {

    private final TransactionRepository repo;
    private final AtomicInteger counter = new AtomicInteger(1000);

    public TransactionController(TransactionRepository repo) {
        this.repo = repo;
    }

    // GET /api/v1/transactions — list all
    @GetMapping
    public List<Transaction> getAll() {
        return repo.findAll();
    }

    // GET /api/v1/transactions/{id} — find one
    @GetMapping("/{id}")
    public ResponseEntity<Transaction> getById(@PathVariable String id) {
        return repo.findById(id)
                   .map(t -> ResponseEntity.ok(t))
                   .orElse(ResponseEntity.notFound().build());
    }

    // POST /api/v1/transactions — record a new transaction
    @PostMapping
    public ResponseEntity<Transaction> create(@RequestBody Transaction txn) {
        String id = "TXN" + counter.incrementAndGet();
        txn.setTransactionId(id);
        Transaction saved = repo.save(txn);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

    // GET /api/v1/transactions/account/{accountId} — by sender
    @GetMapping("/account/{accountId}")
    public List<Transaction> getByAccount(@PathVariable String accountId) {
        return repo.findByFromAccountId(accountId);
    }
}

Step 4 — Start the App and Test

04

Make sure MySQL is running and icicidb database exists. Then:

mvn spring-boot:run

Look for ddl-auto=update in the logs — Hibernate will auto-create the transactions table.

Test with Postman or curl:

1. Record a fund transfer (POST)

POST http://localhost:8080/api/v1/transactions
Content-Type: application/json

{
  "fromAccountId": "ACC001",
  "toAccountId":   "ACC002",
  "amount":        25000.00,
  "transactionType": "DEBIT",
  "remarks":       "Rent payment"
}

Expected response: 201 Created with transactionId: "TXN1001"

2. List all transactions (GET)

GET http://localhost:8080/api/v1/transactions

3. Get by ID (GET)

GET http://localhost:8080/api/v1/transactions/TXN1001

4. Get all transactions from account (GET)

GET http://localhost:8080/api/v1/transactions/account/ACC001
✅ Checkpoint — POST returns 201 with a TXN-prefixed ID. GET /transactions returns the list. Restart the app; the data should still be there (MySQL persists it, unlike H2 in-memory).

Step 5 — Verify Directly in MySQL

05

Open a MySQL shell and confirm the data is really in the database:

mysql -u root -p icicidb

SHOW TABLES;
-- Expected: transactions

DESCRIBE transactions;
-- Expected: transaction_id, from_account_id, to_account_id, amount, transaction_type, remarks

SELECT * FROM transactions;
-- Expected: rows you inserted via POST
💡 This is the key difference from Day 3's H2 — data survives application restarts because MySQL writes to disk.
