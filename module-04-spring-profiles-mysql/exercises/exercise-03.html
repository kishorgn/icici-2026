Exercise 03 — Pagination & Sorting

Module 04: Spring Profiles + MySQL | ICICI Bank API Services | Day 4

⏱ 45 Minutes · Individual
Difficulty: Intermediate
Builds on: Exercise 02
Goal: Add a paginated GET endpoint with sort support

The Problem Without Pagination

Your current GET /api/v1/customers returns all customers in one response. With 5 records this is fine. At ICICI scale — tens of millions of customers — this query would time out, consume gigabytes of memory, and crash the server.

You will add a second endpoint GET /api/v1/customers/page that accepts page, size, and sort parameters and returns a Page<Customer> — a paginated slice with metadata.

Part A — Repository Change

A
1
Add these imports to CustomerRepository.java:
import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
2
Add the pageable override inside the interface body:
Page<Customer> findAll(Pageable pageable);
💡 JpaRepository already has this method. Adding it explicitly is optional but makes the intent visible — a good habit.

Part B — Controller Endpoint

B
3
Add these imports to CustomerController.java:
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Pageable;
import org.springframework.data.domain.Sort;
4
Add this endpoint method inside CustomerController:
// GET /api/v1/customers/page?page=0&size=3&sort=name
@GetMapping("/page")
public Page<Customer> getCustomersPage(
        @RequestParam(defaultValue = "0")    int page,
        @RequestParam(defaultValue = "3")    int size,
        @RequestParam(defaultValue = "name") String sort) {

    Pageable pageable = PageRequest.of(page, size, Sort.by(sort));
    return customerRepository.findAll(pageable);
}

Part C — Test in Postman

C

Start the application and send these requests. Verify each expected response.

GET /api/v1/customers/page3 customers, page 0, totalElements=5, totalPages=2
GET /api/v1/customers/page?page=12 customers, page 1, last=true
GET /api/v1/customers/page?size=5All 5 customers, totalPages=1
GET /api/v1/customers/page?sort=mobileSorted by mobile number
GET /api/v1/customers/page?page=99content: [], empty=true
✓ Page response structure to confirm:
content — the list of customers
totalElements: 5 — total records in DB
totalPages: 2 — with default size=3
first: true on page 0, last: true on page 1

Part D — Stretch Goals

D
  1. Add a maximum size guard: if size > 20, set size = 20 before creating the Pageable.
  2. Try sorting by a field that doesn't exist (e.g. sort=xyz) — observe the error. Return 400 Bad Request instead of a 500.
  3. Add the same /page endpoint to the AccountController (hint: it is identical in structure).
